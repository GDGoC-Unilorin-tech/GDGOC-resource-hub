## Agree on a task

Use the [contribution pathway](/web-development/frontend/contribution-pathway) to prepare your evidence. Confirm scope and acceptance checks with a maintainer. The repository's current origin is [GDGOC-resource-hub](https://github.com/GDGoC-Unilorin-tech/GDGOC-resource-hub).

## Set up your copy

Fork the repository to your GitHub account. Replace YOUR_USERNAME below with your username, then run:

```bash
git clone https://github.com/YOUR_USERNAME/GDGOC-resource-hub.git
cd GDGOC-resource-hub
git switch -c feat/your-change
npm install -g mint
mint dev
```

Use a Node.js version supported by the installed CLI. Open the local address printed by Mintlify. Stop it with Ctrl+C. If you already have a checkout, use that checkout and inspect `git status` before making changes.

## Follow the content structure

Read `site-restructure.md`. Keep one topic per MDX page, with learning objectives, examples, practice, hints, a separate suggested solution, and a completion checklist. Register new pages in `docs.json` in the intended order. Keep external learning references Google-affiliated and on the further-learning page. Use language-tagged code blocks and the existing callout components.

Do not place runnable example CSS or JavaScript in the documentation tree: store them as `.css.source` and `.js.source`, and use the asset build script to produce downloadable runnable files. This prevents example styles and scripts from affecting the hub itself.

## Verify and submit

Preview changed pages, follow their sidebar and previous/next links, open downloads, and run the examples. Check keyboard use and narrow layouts when changing UI. Inspect `git diff` and stage only files belonging to your task.

```bash
git add path/to/changed-file.mdx
git commit -m "docs: clarify the project setup exercise"
git push -u origin feat/your-change
```

Open a pull request against the maintainer-designated base branch. Explain the problem, change, validation, and limitations. Address feedback before maintainers merge or release it. Use `feat:` for a new feature, `fix:` for a repair, and `docs:` for documentation changes.
