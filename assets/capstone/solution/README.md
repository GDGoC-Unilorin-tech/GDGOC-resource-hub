# Integrated frontend capstone

This fictional worked example combines the HTML pages, CSS final design, and JavaScript project explorer. Personalise it before submission. The practice contact form does not send messages.

The download includes public/ with runnable files and REVIEW.md outside the public folder. From the extracted folder, follow the hub's capstone deployment page to initialise Firebase Hosting with public as its directory and no SPA rewrites. Use the Hosting emulator and open its printed local URL. You may instead use an existing HTTP static server pointed at public/. Do not double-click HTML files: fetch and ES modules need HTTP.

Open projects.html for the integrated explorer and tests.html for ten logic checks. Keep tests.html and tests.js only while testing; remove them from your public release if desired. Repeat REVIEW.md manually. Check every other HTML page before release.

Repository source files use .css.source and .js.source to avoid Mintlify injecting demonstration code into the hub. build_archives.py removes that suffix when generating the ZIP. The downloaded public/ files already have the runnable extensions.
