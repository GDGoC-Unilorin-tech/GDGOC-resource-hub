## What you will learn

Separate request behaviour from presentation.

## Before you begin

Work through the previous page and use the extracted practice pack. Keep changes in your own practice branch.

## Understand the idea

A custom Hook is a function starting with use that composes Hooks. It shares stateful logic, not one global state instance: two components calling it normally receive independent state. Keep its return value small and explicit so callers can render all phases.

The pack's useProjects returns phase, projects, error, and reload. Explorer owns presentation and filters; useProjects owns the request lifecycle. Do not call a Hook conditionally or hide dependencies to force an Effect to run less often. The beginner component needs no data-loading Hook because its data is local.

## Worked example

```jsx
function ProjectPanel() {
  const { phase, projects, error, reload } = useProjects();
  if (phase === 'error') return <div>
    <p role="status">{error}</p><button onClick={reload}>Retry</button>
  </div>;
  return <p>{phase === 'loading' ? 'Loading…' : `${projects.length} projects`}</p>;
}
```

## Practice challenge

Explain the responsibility of useProjects and Explorer. Temporarily mount two ProjectPanel instances and observe whether their reload state is shared.

<Accordion title="Need a hint?">

A function name does not make state global. Each call creates its own Hook state.

</Accordion>
