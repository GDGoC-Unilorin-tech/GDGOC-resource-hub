## What you will learn

Synchronise with a request and clean up obsolete work.

## Before you begin

Work through the previous page and use the extracted practice pack. Keep changes in your own practice branch.

## Understand the idea

An Effect synchronises a component with something outside rendering, such as a network request. Fetching is not a calculation to perform during render. Track loading, error, and success states separately, validate the response, and provide retry.

Inspect useProjects in the pack. An AbortController cancels work on cleanup; an active flag also prevents obsolete results from updating the component. Dependencies must describe the values the Effect uses. Development StrictMode can run an extra setup/cleanup cycle to reveal missing cleanup; do not remove it just to hide duplicated development requests.

## Worked example

```jsx
useEffect(() => {
  let active = true;
  const controller = new AbortController();
  setResult({ phase: 'loading', projects: [], error: '' });
  loadProjects(controller.signal).then(projects => {
    if (active) setResult({ phase: 'ready', projects, error: '' });
  }).catch(error => {
    if (active && error.name !== 'AbortError') {
      setResult({ phase: 'error', projects: [], error: error.message });
    }
  });
  return () => { active = false; controller.abort(); };
}, [attempt]);
```
