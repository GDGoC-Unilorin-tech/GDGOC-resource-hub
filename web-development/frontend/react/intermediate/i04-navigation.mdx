## Understand the idea

A tab stored only in React state cannot be shared through its URL. For this small client-side exercise, the pack uses the hash fragment to choose Home, Projects, or About. Anchors update the hash; a hashchange listener updates React state, and browser Back can restore the prior view. Unknown fragments show a not-found message.

This is an educational hash navigator, not a replacement for a routing library in a larger application. Path routing, nested layouts, data loaders, server rendering, and route error boundaries need additional design. Hash routes leave the server path unchanged, so they do not require a catch-all rewrite.

## Worked example

```jsx
useEffect(() => {
  const update = () => setRoute(readRoute());
  window.addEventListener('hashchange', update);
  return () => window.removeEventListener('hashchange', update);
}, []);
// <a href="#/projects">Projects</a>
```

## Practice challenge

<Accordion title="Need a hint?">

The URL is the source of route state; buttons that only set local state do not update history.

</Accordion>

<Accordion title="View a suggested solution">

The direct About hash renders About. Back restores the earlier hash/view. Unknown fragments show Not found and a Home link. A hash change does not request a separate HTML page.

</Accordion>
