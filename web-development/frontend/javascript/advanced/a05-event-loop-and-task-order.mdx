## Understand the idea

JavaScript executes the current synchronous work first. Promise continuations are queued as microtasks; a timer callback is scheduled as a task. Microtasks run after the current execution finishes and before the next task is taken. A zero-delay timer is not an instruction to run immediately.

Long synchronous work can prevent the page from responding. Marking a function async does not move heavy computation off the main thread. Use measurements before optimisation; later you will practise breaking work into smaller tasks.

## Run the example

```javascript
console.log("start");
setTimeout(() => console.log("timer"), 0);
Promise.resolve().then(() => console.log("promise"));
console.log("end");
```

**Expected result:** Output order is start, end, promise, timer.

## Practice challenge

Write an async function that logs Before, awaits Promise.resolve(), then logs After. Call it and immediately log Outside. Predict the sequence before running.

### Completion checklist

- [ ] The order is Before, Outside, After.
- [ ] I can explain why Outside is not last.
- [ ] I do not treat async as background computation.
