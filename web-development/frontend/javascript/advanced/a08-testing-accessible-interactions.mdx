## Understand the idea

A DOM test can check that a button updates its controlled region and its aria-expanded value. Native buttons provide keyboard behaviour; ARIA communicates state but does not implement the interaction. Keep state and visible content synchronised.

Automated clicks do not replace manual keyboard and assistive-technology checks. Test Tab focus, Enter/Space activation, and whether focus remains usable after content changes. Avoid moving focus unnecessarily for a simple disclosure.

## Run the example

```javascript
const button = document.querySelector("#toggle");
const notes = document.querySelector("#notes");
button.addEventListener("click", () => {
  const open = button.getAttribute("aria-expanded") === "true";
  button.setAttribute("aria-expanded", String(!open));
  notes.hidden = open;
  button.textContent = open ? "Show notes" : "Hide notes";
});
```

**Expected result:** The button alternates visibility, label, and expanded state. Focus stays on the button.

## Practice challenge
