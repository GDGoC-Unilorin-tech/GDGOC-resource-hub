## Understand the idea

Debugging starts with a specific expected result and a repeatable actual result. Syntax errors stop code from being parsed; reference errors often mean a name is wrong; logic errors produce an incorrect result without throwing.

In Chrome DevTools, open Sources, select app.js, and click a line number to add a breakpoint. Reload or activate the feature, then use Step over to follow execution and inspect local values. Change the saved source file to keep a fix; a temporary DevTools edit may not survive refresh.

## Run the example

```javascript
function averageMinutes(first, second) {
  const total = first + second;
  return total / 2;
}
console.log(averageMinutes(10, 30));
console.log(averageMinutes(0, 0));
```

**Expected result:** Results are 20 and 0. Pause on the return line and inspect total for each call.

## Practice challenge

Investigate a calculation written as first + second / 2 instead of (first + second) / 2. For 10 and 30 it gives 25. Fix the function and test equal inputs (8, 8) and zeros. Record the cause in a comment.

### Completion checklist

- [ ] Results are 20, 8, and 0.
- [ ] I can reproduce and explain the original defect.
- [ ] I verified the saved file after refresh.

```javascript
function averageMinutes(first, second) {
  // Add before dividing; without parentheses only second is halved.
  return (first + second) / 2;
}
console.log(averageMinutes(10, 30));
console.log(averageMinutes(8, 8));
console.log(averageMinutes(0, 0));
```

Explain why it meets each checklist item. Different implementations can be correct.
