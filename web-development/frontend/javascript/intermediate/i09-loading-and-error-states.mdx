## Understand the idea

An asynchronous interface needs more than a success message. Show loading while waiting, an empty message for a valid empty result, and a recoverable error for failure. Disable the action during a single in-flight request to prevent duplicate work.

`finally` runs after try/catch regardless of success or failure, so it is useful for restoring the button. An error message should explain what the user can do next. Keep status text in a live region already present before the update.

Run over HTTP with the same local `projects.json`. Use Network throttling in DevTools to observe the loading state.

## Run the example

```javascript
const button = document.querySelector("#load");
const status = document.querySelector("#status");
button.addEventListener("click", async () => {
  button.disabled = true;
  status.textContent = "Loading projects…";
  try {
    const response = await fetch("./projects.json");
    if (!response.ok) throw new Error("Request failed");
    const data = await response.json();
    if (!Array.isArray(data)) throw new Error("Invalid list");
    status.textContent = data.length === 0 ? "No projects yet" : `${data.length} projects loaded`;
  } catch (error) {
    status.textContent = "Could not load projects. Try again.";
  } finally {
    button.disabled = false;
  }
});
```

**Expected result:** The button loads 2 projects, and is enabled again afterward. [] gives No projects yet; a missing file gives a retry message.

const button = document.querySelector("#load");
