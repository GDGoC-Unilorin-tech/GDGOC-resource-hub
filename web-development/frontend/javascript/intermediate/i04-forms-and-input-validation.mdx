## Understand the idea

Listen for the form's `submit` event so clicking its button and pressing Enter follow the same path. `event.preventDefault()` stops navigation for this local demo. Native validation runs before a normal submit event; keep useful HTML constraints.

An input's `value` is a string. Check empty text before `Number(...)`, because an empty string converts to zero. `Number.isInteger` rejects fractions, infinities, and NaN. Client-side checks help users but are not a security boundary; a real backend must validate independently.

## Run the example

```javascript
const form = document.querySelector("#session");
form.addEventListener("submit", event => {
  event.preventDefault();
  const input = document.querySelector("#minutes");
  const minutes = Number(input.value);
  const result = document.querySelector("#result");
  if (input.value.trim() === "" || !Number.isInteger(minutes) || minutes < 1 || minutes > 120) {
    result.textContent = "Enter a whole number from 1 to 120.";
    input.focus();
    return;
  }
  result.textContent = `Recorded ${minutes} minutes for this visit.`;
});
```

**Expected result:** Submitting 25 reports 25 minutes without navigation. Empty, fractional, and out-of-range entries are rejected by the form.
