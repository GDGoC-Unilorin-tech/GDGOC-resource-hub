## Understand the idea

`fetch` returns a promise for a Response. A 404 response does not automatically reject that promise: inspect `response.ok` before consuming data. `response.json()` is also asynchronous and may fail if the response is not valid JSON.

Use the local projects.json from the preceding lesson. Keep the server running. `Array.isArray` checks that the result is an array. Do not disable browser security to work around fetch errors; check the server URL, filename, and Network panel.

Use the HTTP server and `projects.json` fixture from the previous lesson. Save this script in the same folder.

## Run the example

```javascript
async function loadProjects() {
  try {
    const response = await fetch("./projects.json");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const projects = await response.json();
    if (!Array.isArray(projects)) throw new Error("Expected an array");
    console.log(projects.length);
  } catch (error) {
    console.log("Projects unavailable");
  }
}
loadProjects();
```

**Expected result:** The supplied file logs 2. Renaming it temporarily produces Projects unavailable.

```javascript
async function loadProjects() {
  try {
    const response = await fetch("./projects.json");
    if (!response.ok) throw new Error("HTTP failure");
    const data = await response.json();
    if (!Array.isArray(data) || !data.every(item => item !== null && typeof item === "object" && typeof item.title === "string")) {
      throw new Error("Invalid project data");
    }
    for (const item of data) console.log(item.title);
  } catch (error) {
    console.log("Projects unavailable");
  }
}
loadProjects();
```
