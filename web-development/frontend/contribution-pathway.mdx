**Learn → Practise → Build → Demonstrate → Contribute → Ship**

## Prepare your evidence

Complete the [capstone review](/web-development/frontend/capstone/review). Keep your repository, live URL, test record, and demo together. Explain what you can maintain and where you still need support.

<Info>The technical team decides available tasks, reviewers, repository access, and release approval. This guide prepares you for that conversation; course completion does not automatically grant a role or production access.</Info>

## Choose a small contribution

Ask maintainers to confirm the problem and scope before taking a task. Good first contributions to this hub include repairing a reproducible broken internal link, clarifying an exercise, adding a tested example, or fixing a keyboard navigation defect.

Write a short proposal: current behaviour, desired behaviour, affected pages, and how you will verify the change. Avoid combining an unrelated redesign with a content correction.

## Build and request review

Follow [How to contribute](/how-to-contribute). Create a focused branch, make the change, preview affected pages, and check navigation and links. Submit a pull request explaining the problem, change, checks, and remaining limitations. Include screenshots when the appearance changes. Address review feedback and rerun affected checks. Maintainers decide merge and release timing.

## Practice: propose your first task

Find one unclear instruction in a lesson you completed. Write the learner's confusion, a proposed correction, and a check that would prove the correction works. Do not change lesson scope without discussing it with its maintainer.

<Accordion title="Suggested proposal">
“The exercise asks learners to open projects.html but does not say to start the local server. I propose adding the existing server instructions before that step. I will follow the lesson from a fresh extracted folder and verify that the JSON request succeeds.”
</Accordion>

## Ready-to-submit checklist

- [ ] The maintainer confirmed the task and acceptance criteria.
- [ ] My change is focused and follows the existing lesson structure.
- [ ] Examples, links, and download instructions were tested.
- [ ] External learning references are Google-affiliated and placed in further learning.
- [ ] My pull request includes evidence and known limitations.
- [ ] I can explain and revise the change in response to review.
