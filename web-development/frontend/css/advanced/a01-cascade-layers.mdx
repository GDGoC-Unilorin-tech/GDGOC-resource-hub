## What you will learn

- Declare an explicit layer order.
- Distinguish layer priority from specificity.
- Avoid accidental unlayered overrides.

## Understand the idea

Cascade layers group author styles into an explicit priority order. For normal declarations, later layers win over earlier layers before selector specificity is compared. A layer order statement at the top makes the intended hierarchy visible even when rules are written elsewhere.

Normal unlayered author declarations outrank normal declarations in named layers. Therefore, wrapping a few new rules in a layer while leaving conflicting old rules unlayered can give unexpected results. Migrate deliberately and inspect the winner. Important declarations reverse layer precedence; this lesson avoids !important so the normal ordering stays clear.

Layers do not change how a selector matches or how layout works. They organise competing declarations. Use a few purposeful layers rather than one for every component.

## Worked example

### HTML body

```html
<h1>Layered component</h1>
<article class="card featured"><h2>Portfolio</h2><p>A reusable component with an intentional variation.</p></article>
```

### styles.css

```css
@layer base, components, utilities;
@layer base { body { font-family: system-ui, sans-serif; } }
@layer components { .card.featured { padding: 1rem; color: #174ea6; } }
@layer utilities { .featured { color: #137333; } }
```

<Tip>CSS examples belong in your practice project's stylesheet. They are displayed as code here; copying them into an MDX page does not style your practice HTML.</Tip>

## Try it and observe

The featured card is green even though .card.featured is more specific than .featured: the later normal layer wins first. Temporarily add an unlayered .featured colour rule and observe its priority, then remove it.

## Practice challenge

Keep the three layers, make the utility override purple (#6a1b9a), and add a 1px border in the components layer. Do not use !important or an unlayered colour rule.

Save your changes, reload, and compare the observed result with your prediction. Keep a short note of what changed and why.

<Accordion title="Need a hint?">

Put structural component styling in components and the intentional variation in utilities.

</Accordion>

## Check your understanding

Why might an old unlayered rule beat your new component layer?
