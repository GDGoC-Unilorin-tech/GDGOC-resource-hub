## What you will learn

- Combine HTML dimensions with flexible CSS sizing.
- Distinguish containment from cropping.
- Provide local overflow only when the content needs it.

## Understand the idea

HTML width and height communicate an image’s proportions before it loads. CSS can make its displayed size flexible. `max-width:100%; height:auto` allows an image to shrink to its container while preserving its aspect ratio. Display:block removes the inline baseline gap when the image is a standalone block.

Object-fit matters when the element has a constrained box. Cover fills that box and crops excess content; contain fits the whole image and can leave empty space. Do not crop diagrams, text screenshots, or other images whose edges carry essential information just to make all cards equal.

A wide data table may need local horizontal scrolling. Put it in a labelled, keyboard-focusable wrapper with overflow:auto rather than making the entire page scroll horizontally. Check that the focus outline remains visible.

## Worked example

### HTML body

```html
<h1>Learning diagram</h1>
<img class="diagram" src="images/study-wide.png" width="960" height="540" alt="Learn, practise, then build">
<div class="table-wrap" role="region" aria-label="Study schedule" tabindex="0"><table><caption>Study schedule</caption><tr><th scope="col">Topic</th><th scope="col">Task</th></tr><tr><td>Images</td><td>Check that diagrams remain fully visible</td></tr></table></div>
```

### styles.css

```css
.diagram { display: block; max-width: 100%; height: auto; }
.table-wrap { max-width: 100%; overflow: auto; }
.table-wrap:focus { outline: 3px solid #174ea6; outline-offset: 2px; }
```

## Practice challenge

Constrain the diagram’s displayed width to at most 40rem while allowing it to shrink. Centre it with auto horizontal margins. Preserve its full composition.

Save your changes, reload, and compare the observed result with your prediction. Keep a short note of what changed and why.

<Accordion title="Need a hint?">

Use width:100% with max-width:40rem and height:auto; object-fit:cover is unnecessary here.

</Accordion>

## Check your understanding

Is object-fit:cover always the right fix for a large image?

<Accordion title="Check your answer">

No. It crops to fill a constrained box. A diagram often needs its entire content preserved, so proportional shrinking or contain is more appropriate.

</Accordion>
