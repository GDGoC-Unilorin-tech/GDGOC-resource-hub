## Understand the idea

Min() chooses the smallest of its arguments; max() chooses the largest. Clamp(minimum, preferred, maximum) constrains a preferred value between two bounds. These functions let a property adapt without a separate media query at every size.

For a heading, a preferred value combining rem and viewport units can grow with available space while retaining a font-relative contribution. A pure vw font size can become too small or respond poorly to text enlargement. Even a mixed clamp formula requires testing: a maximum can limit growth, and real headings can be much longer than your example.

Use fluid space deliberately. Every gap does not need to change constantly. A small consistent spacing scale is often easier to maintain than many unrelated formulas.

## Worked example

### HTML body

```html
<main class="hero"><h1>Building useful things through steady practice</h1><p>My frontend learning portfolio.</p></main>
```

### styles.css

```css
.hero { padding: clamp(1rem, 3vw, 3rem); max-width: 65ch; }
.hero h1 { font-size: clamp(2rem, 1.5rem + 2vw, 3rem); line-height: 1.15; overflow-wrap: anywhere; }
```

## Try it and observe

Record the heading’s computed font size at 320px and 1280px. It should stay between 2rem and 3rem. Zoom to 200% and check the full heading remains visible; do not assume the formula alone guarantees accessibility.

## Practice challenge

Make the heading range from 1.75rem to 2.75rem with preferred 1.25rem + 2vw. Keep fluid padding and wrapping.

Save your changes, reload, and compare the observed result with your prediction. Keep a short note of what changed and why.

<Accordion title="Need a hint?">

The first and third clamp arguments are bounds, not breakpoints.

## Check your understanding

Does clamp choose one of three viewport breakpoints?

<Accordion title="Check your answer">

No. It evaluates values for the property, uses the preferred value when it lies within the bounds, and otherwise uses the appropriate bound.
