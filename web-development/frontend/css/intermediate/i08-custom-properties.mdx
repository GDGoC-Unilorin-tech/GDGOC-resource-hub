## Understand the idea

Custom properties have names beginning with two hyphens. Declare shared values on :root and use them with var(). They participate in the cascade and ordinarily inherit, so a value declared on a component can affect its descendants without changing the rest of the page.

Name values by role, such as --surface or --space-card, rather than assuming a colour will always be blue. Reusing a few intentional values makes later theme and spacing changes easier to inspect. Custom property names are case-sensitive.

The second argument to var() is a fallback when the referenced property is missing or invalid as a custom property. It is not a general validator for every consuming property: if --space is defined as red, padding:var(--space, 1rem) does not simply choose 1rem because red is an invalid padding value.

## Worked example

### HTML body

```html
<h1>Reusable cards</h1>
<article class="card"><h2>Portfolio</h2><p>Standard card.</p></article>
<article class="card featured"><h2>Study journal</h2><p>A scoped variation.</p></article>
```

### styles.css

```css
:root { --accent: #174ea6; --space-card: 1rem; }
.card { color: var(--accent); padding: var(--space-card); border: 1px solid currentColor; margin-bottom: 1rem; }
.featured { --accent: #137333; }
```

## Try it and observe

Change --accent on :root: the ordinary card changes, but the featured card keeps its local green value. Inspect the inherited custom property on each heading.

## Practice challenge

Set shared card padding to 1.5rem and make the featured card purple (#6a1b9a), without copying the entire .card rule.

Save your changes, reload, and compare the observed result with your prediction. Keep a short note of what changed and why.
