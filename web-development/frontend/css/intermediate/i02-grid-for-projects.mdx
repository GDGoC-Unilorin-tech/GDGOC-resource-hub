- Use fr, repeat, minmax, and auto-fit.

## Understand the idea

Grid controls rows and columns. Setting display:grid on the parent makes its direct children grid items. Fr units divide available space; gap separates tracks. `repeat(3, 1fr)` creates three equal tracks, but a fixed count is not always suitable for small screens.

Auto-fit with minmax can create as many columns as fit. A minimum of 15rem gives cards a useful starting width, but an unconditional 15rem minimum could overflow a smaller container. `min(100%, 15rem)` caps that minimum at the available width. The maximum 1fr lets cards share remaining space.

Keep the source in a meaningful order. A visual grid does not change what order a keyboard user follows. Long card text may need min-width:0 and overflow-wrap to avoid an oversized intrinsic minimum.

## Worked example

### HTML body

```html
<h1>My projects</h1>
<div class="projects"><article><h2>Portfolio</h2><p>Semantic HTML pages.</p></article><article><h2>Study log</h2><p>A record of practice.</p></article><article><h2>Event page</h2><p>A community event outline.</p></article></div>
```

### styles.css

```css
.projects { display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 15rem), 1fr)); gap: 1rem; }
.projects article { min-width: 0; padding: 1rem; border: 1px solid #747775; overflow-wrap: anywhere; }
```

## Try it and observe

Resize the page and count columns. Inspect the grid overlay. Insert a long project title and confirm it wraps instead of forcing horizontal overflow.

## Practice challenge

Change the preferred card minimum to 18rem and the gap to 1.5rem. Add a fourth article and confirm it joins the layout without a new selector.

Save your changes, reload, and compare the observed result with your prediction. Keep a short note of what changed and why.

## Check your understanding

Why is a fixed 18rem minimum risky without the min(100%, ...) safeguard?
