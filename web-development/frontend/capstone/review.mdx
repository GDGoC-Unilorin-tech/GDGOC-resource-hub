title: "Demonstrate and review your capstone"
description: "Prepare evidence and use an observable review rubric."
---


## Submission package

Provide a source repository, live URL, setup README, audience statement, test record, known limitations, and a short demo. Include attribution for reused assets and explain the work you personally completed. A copied solution without explanation or adaptation is not evidence of independent skill.

## Review rubric

For each row use **Ready**, **Needs revision**, or **Not tested**, and add evidence. The capstone is ready for a contribution discussion when every row is Ready. This is a learning rubric, not an automatic team admission decision.

| Area | Ready means |
| --- | --- |
| Purpose and content | Five connected pages support the stated audience; project descriptions explain real learning |
| HTML and accessibility | Meaningful structure, labelled forms, alternatives, keyboard access, and visible focus pass recorded checks |
| CSS and layout | Shared design works at narrow/wide sizes, zoom, dark mode, reduced motion, and print |
| JavaScript | Search/filter/sort/reset work together; validation, empty/error states, retry, storage failure, and stale requests are handled |
| Resilience | Essential information works without JavaScript; contact functionality is described accurately |
| Verification | Test record includes actual results, repairs, and retests; remaining limitations are explicit |
| Delivery | Setup is reproducible, preview feedback addressed, deployed links and assets verified |
| Explanation | Learner can explain one design decision, one state transition, and one repaired defect |

## Practice: give a five-minute demonstration

Show the visitor journey, demonstrate one interaction, trigger and recover from one failure, then explain a repair. Ask a peer to run your setup steps without verbal help. Record what they could not reproduce.

<Accordion title="Hint">
Use specific evidence: the file you changed, the test that failed, and the retest result. A screenshot alone cannot prove that keyboard interaction works.
</Accordion>

<Accordion title="Suggested review response">
“Needs revision: at 320px the reset control was outside the viewport. I changed the controls to wrap, retested at 320px and 400% zoom, and attached the results. The practice form still has no backend, which is stated beside the form.”
</Accordion>

## Completion checklist

- [ ] Every rubric row has a result and evidence.
- [ ] My reviewer can run the project using the README.
- [ ] I addressed feedback or documented why a change is deferred.
- [ ] I can explain my code without reading the suggested solution.
