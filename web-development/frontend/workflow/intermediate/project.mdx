## Project brief

Repair the three supplied starter defects: panel overflow, string concatenation, and the incorrect data URL. Keep one focused commit per repair and a defect record with reproduction steps, source cause, fix, and retest. Preserve labels, status messages, and reload behaviour.

## Acceptance criteria

At 320px the page fits; 2 and 3 produce 5; items.json loads three entries; empty and failed requests have distinct messages.

## Build and review

1. Write the expected outcome before editing.
2. Work in your practice repository on a focused branch.
3. Inspect changes, run the relevant checks, and commit a coherent result.
4. Ask a peer to follow the record; capture their feedback and your retest.

## Completion checklist

- [ ] I met each acceptance criterion or recorded what remains incomplete.
- [ ] My files and written setup instructions agree.
- [ ] My test record contains actual results.
- [ ] I can explain the change without reading the solution.

Use templates/PULL_REQUEST.md, DEFECT.md, TEST_RECORD.md, and RELEASE.md as appropriate. Keep hypothetical outcomes separate from observations.
