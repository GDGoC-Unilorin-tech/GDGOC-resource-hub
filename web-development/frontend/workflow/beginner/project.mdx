## Project brief

Create a clean practice repository with a useful README, at least two focused commits, a feature branch, and an evidence-based review request. Have a peer follow the setup instructions. Record whether you actually pushed and opened a pull request or prepared it locally.

## Acceptance criteria

The reviewer can start the site, identify the intended change, and distinguish local commits from remote review.

## Build and review

1. Write the expected outcome before editing.
2. Work in your practice repository on a focused branch.
3. Inspect changes, run the relevant checks, and commit a coherent result.
4. Ask a peer to follow the record; capture their feedback and your retest.

## Completion checklist

- [ ] I met each acceptance criterion or recorded what remains incomplete.
- [ ] My files and written setup instructions agree.
- [ ] My test record contains actual results.
- [ ] I can explain the change without reading the solution.

<Accordion title="Hints">
Use templates/PULL_REQUEST.md, DEFECT.md, TEST_RECORD.md, and RELEASE.md as appropriate. Keep hypothetical outcomes separate from observations.
</Accordion>

<Accordion title="Suggested solution and review">

The correct code is only part of this project: your commits, explanation, and evidence must describe your own work. A copied sample report is not proof of a completed review or release.
</Accordion>
