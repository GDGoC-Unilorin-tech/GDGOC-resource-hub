## What you will learn

- Inspect source and the browser document tree.
- Recognise browser error recovery.
- Repair nesting, path, and fragment defects.

## Before you begin

Complete the previous lesson in this module. Keep your editor and browser ready.

<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## Look at both the result and the markup

View Source shows the document source; the browser's Elements inspector shows the parsed document tree, which the browser may have repaired. Right-click an element and choose Inspect to find that part of the tree. Menu names vary by browser.

## A repeatable debugging process

Describe the symptom, find the relevant source, change one thing, save, and retest. Broken images often mean the path or filename is wrong. A fragment that does nothing may have a mismatched ID. Unexpected nesting may come from closing tags in the wrong order.

HTML comments use `<!-- comment -->`. They document intent and are not displayed as page text, but visitors can read them in the source. Never put secrets in comments.

## Worked example

```html
<!-- Deliberately broken: repair before using -->
<p>I practise <strong>HTML</p></strong>
<a href="#goals">My goals</a>
<h2 id="goal">My goals</h2>
<img src="image/study-wide.png" alt="Learn, practise, build">
```

This snippet has three defects: crossed closing tags, a fragment mismatch, and an image-folder typo. The intended folder is images. The browser may still display some content.

<Note>A browser repair can hide the symptom without fixing your source.</Note>

## Practice challenge

Place the broken snippet in a copy of your page, with the supplied image in images. Record each symptom, repair all three defects, and inspect the corrected paragraph.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

<Accordion title="Need a hint?">
Read the opening tags in order, then check closing tags in reverse order.
</Accordion>

## Completion checklist

- [ ] The strong element closes before the paragraph.
- [ ] The fragment and destination ID match.
- [ ] The image path resolves.
- [ ] I recorded symptoms, repairs, and retest results.

<Accordion title="View a suggested solution">

```html
<p>I practise <strong>HTML</strong>.</p>
<a href="#goals">My goals</a>
<h2 id="goals">My goals</h2>
<img src="images/study-wide.png"
     alt="Three stages: learn, practise, build"
     width="960" height="540">
```

This implementation follows the requirements above. Compare it with your own attempt against each checklist item. Your wording and other valid choices may differ. Explain one decision you made and revise any unmet criterion.

</Accordion>
