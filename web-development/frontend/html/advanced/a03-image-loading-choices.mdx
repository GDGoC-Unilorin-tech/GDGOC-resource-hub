## What you will learn

- Reserve image space with dimensions.
- Use lazy loading selectively.
- Explain image loading decisions.

## Reserve space before an image arrives

Accurate width and height give the browser an aspect ratio so it can reserve space. This reduces content movement as the image loads. CSS may later resize the image, but its intrinsic proportions remain useful.

## Load according to importance

`loading="lazy"` asks the browser to defer loading an image until it is near the viewport. It is a hint, and browsers choose the threshold. It does not guarantee an offscreen image remains unloaded until you scroll.

Do not automatically lazy-load the prominent image visible when the page opens. Defer suitable below-the-fold images instead. Compression, sensible dimensions, and appropriate formats also affect weight; HTML attributes cannot rescue enormous unnecessary assets.

## Worked example

```html
<!-- Prominent introductory image -->
<img src="images/study-wide.png" width="960" height="540"
     alt="Learn, practise, build">

<!-- An image later in a long page -->
<img src="images/study-small.png" width="480" height="270"
     loading="lazy" alt="A reminder of the three learning stages">
```

Use the second image only where its content is useful. Its smaller file and loading hint suit a later section; do not add duplicate decoration solely to demonstrate lazy loading.

<Note>Do not promise a performance improvement without measuring the actual page.</Note>

## Try it and observe

### Observe loading without assuming a threshold

Keep one useful image near the top and another in a later section of a genuinely long page. Open Network, filter to images, disable cache while DevTools is open, and reload. Record when each request appears before and after scrolling. A lazy image may already load near the viewport; that is not proof the attribute failed. Keep a short explanation of why each placement suits its loading choice.

## Practice challenge

Review two image placements in your portfolio. Add accurate dimensions, choose which should be deferred, and write a short justification. Inspect Network requests without treating browser heuristics as a strict pass/fail rule.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

<Accordion title="Need a hint?">
Review where the visitor first needs the image, not just how many images exist.
