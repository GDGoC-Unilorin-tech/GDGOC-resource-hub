## What you will learn

- Recognise invalid content relationships.
- Avoid nested interactive controls and duplicate IDs.
- Distinguish parsed markup from valid source.

## Before you begin

Complete the Intermediate portfolio milestone and earlier lessons in this module.

<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## HTML has content rules

Elements cannot be combined arbitrarily. A paragraph holds phrasing content; headings and sections belong outside it. Links must not contain buttons or other links. IDs must be unique within a document.

The browser's parser recovers from many mistakes, sometimes closing a paragraph earlier than you wrote it or moving nodes. The Elements panel shows that recovered tree. Always inspect your saved source as well.

## Repair meaning rather than appearance

If a card navigates somewhere, use a descriptive link. If it performs an action, use a button with appropriate behaviour. Do not put a button inside a link to get a particular visual style. This HTML-only course uses links for navigation.

## Worked example

```html
<!-- Incorrect relationships: do not copy into your final page -->
<p>My work<section><h2>Projects</h2></section></p>
<a href="projects.html"><button type="button">Projects</button></a>
<h2 id="goals">Goals</h2>
<h2 id="goals">More goals</h2>
```

The paragraph incorrectly wraps a section, the link wraps an interactive button, and the ID is duplicated. Fix each relationship rather than relying on browser recovery.

<Note>A page that looks right can still contain structural errors.</Note>

## Practice challenge

Repair the example into separate paragraphs/sections, one ordinary navigation link, and unique section IDs. Explain all three changes.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

## Completion checklist

- [ ] Paragraphs contain appropriate content.
- [ ] No interactive element is nested inside another interactive control.
- [ ] All IDs are unique.
- [ ] I compared source with the parsed tree.

<Accordion title="View a suggested solution">

```html
<p>Explore my work below.</p>
<section><h2>Projects</h2><p>My HTML practice projects.</p></section>
<a href="projects.html">Explore projects</a>
<h2 id="goals">Goals</h2>
<h2 id="future-goals">Future goals</h2>
```

This implementation follows the requirements above. Compare it with your own attempt against each checklist item. Your wording and other valid choices may differ. Explain one decision you made and revise any unmet criterion.

</Accordion>
