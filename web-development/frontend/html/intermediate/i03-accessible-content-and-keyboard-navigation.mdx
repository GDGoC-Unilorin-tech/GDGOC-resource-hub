## What you will learn

- Provide descriptive text and sensible navigation.
- Add a working skip link.
- Review a page with a keyboard.

## Before you begin

Complete the Beginner stage project and earlier lessons in this module. Work in a copy of your growing portfolio.

<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## Build on native HTML

Accessibility means people with different abilities and tools can use your content. Meaningful headings, link labels, image alternatives, and form labels are foundations, not optional polish.

Use anchors for navigation and buttons for actions. Avoid making a div act like a button. Avoid positive tabindex values that create a separate focus order; native document order should make sense.

## Let people skip repeated navigation

Place a skip link near the start of body and point it at the main content. `tabindex="-1"` makes the main region programmatically focusable without adding it to the normal Tab sequence.

## Test the journey

Use Tab and Shift+Tab to move through links and controls, and Enter to activate links. Do not remove visible focus indicators. Check heading order and image alternatives in addition to keyboard behaviour. This manual review is useful but not a full accessibility audit.

## Worked example

```html
<a href="#main-content">Skip to main content</a>
<header>
  <nav aria-label="Main"><a href="about.html">About me</a></nav>
</header>
<main id="main-content" tabindex="-1">
  <h1>My portfolio</h1>
  <p><a href="projects.html">Explore my HTML projects</a></p>
</main>
```

The skip link stays visible without CSS, which is fine here. It gives a visitor a direct route past repeated navigation.

<Note>ARIA does not repair incorrect HTML automatically. Prefer an appropriate native element first.</Note>

## Try it and observe

### Follow a keyboard-only route

Reload the page and press Tab until the skip link is focused. Press Enter, then Tab again: focus should continue through the links or controls in the main content instead of repeating the header. Repeat on the second page. Record the browser, the first control reached after skipping, and any unexpected focus jump.

## Practice challenge

Add a skip link to both existing pages. Replace vague link labels, review image alternatives and headings, and record a keyboard-only journey.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

Put the skip link before the repeated navigation. Test from a fresh page load.

## Check your understanding

Why use `tabindex="-1"` on the skip-link target instead of `tabindex="5"`?

Write your answer before opening the explanation.

<Accordion title="Check your answer">

Minus one lets the target receive focus without inserting it in the regular Tab sequence. A positive value changes the normal ordering and can make navigation confusing. Test the actual skip journey rather than judging it only by scrolling.
