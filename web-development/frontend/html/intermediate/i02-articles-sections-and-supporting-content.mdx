## What you will learn

- Choose article, section, and aside by purpose.
- Give sections meaningful headings.
- Avoid unnecessary wrappers.

## Before you begin

Complete the Beginner stage project and earlier lessons in this module. Work in a copy of your growing portfolio.

<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## Related content has relationships

An `article` is a self-contained composition that could make sense on its own, such as a project description or news story. A `section` groups a thematic part of a document, usually with a heading. An `aside` contains supporting content tangentially related to what surrounds it.

Choose based on content, not where you want it positioned. An aside is not automatically a right-hand column. A section is not simply a generic styling box.

Continue using an explicit heading hierarchy. Do not restart every section with h1 and assume the browser creates the hierarchy you intended.

## Worked example

```html
<main>
  <h1>My projects</h1>
  <article>
    <h2>Personal introduction website</h2>
    <p>A two-page site built with HTML.</p>
    <section>
      <h3>What I learned</h3>
      <p>Relative links and meaningful text structure.</p>
    </section>
  </article>
  <aside>
    <h2>Related learning</h2>
    <p>I am practising browser inspection next.</p>
  </aside>
</main>
```

The project description can stand alone as an article. Its learning section is part of that article. Supporting learning information is outside the article.

<Note>You do not need to use every semantic element on every page.</Note>

## Try it and observe

### Choose the element before typing

Write a one-sentence description of each content block. A project case study that stands alone can be an `article`; its Lessons learned part can be a `section`; a related reading note can be an `aside`. Read just the headings aloud. They should describe the document in order without relying on font size.

## Practice challenge

Create two project articles on your portfolio projects page. Give one a Lessons learned subsection and add relevant supporting content only if it serves a purpose.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

<Accordion title="Need a hint?">
Ask: could this content stand alone, is it a part of a larger theme, or is it supporting information?
</Accordion>

## Completion checklist

- [ ] Both articles make sense independently.
- [ ] The subsection has an appropriate heading.
- [ ] Supporting content has a clear relationship.
- [ ] No wrapper was added solely to fill a requirement.

<Accordion title="View a suggested solution">

```html
<h1>My projects</h1>
<article>
  <h2>Introduction site</h2>
  <p>My first connected pages.</p>
  <section><h3>Lessons learned</h3><p>Use clear link text.</p></section>
</article>
<article>
  <h2>Study log</h2>
  <p>A record of my HTML practice.</p>
</article>
<aside><h2>Next practice</h2><p>Review both projects with a keyboard.</p></aside>
```

This implementation follows the requirements above. Compare it with your own attempt against each checklist item. Your wording and other valid choices may differ. Explain one decision you made and revise any unmet criterion.

</Accordion>
