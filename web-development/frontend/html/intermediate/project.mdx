## Project brief

Extend your Beginner portfolio instead of starting a new site. Retain the home and about pages and add projects.html, learning-log.html, and contact.html.

## Requirements and completion checklist

- [ ] Use meaningful header, nav, main, and footer regions on each page.
- [ ] Provide working navigation and skip links across the site.
- [ ] Describe your projects using logical headings and appropriate semantic elements.
- [ ] Add a learning-log table with caption, headers, and appropriate scope.
- [ ] Include a machine-readable date, an attributed quotation, and a displayed code snippet.
- [ ] Build a labelled, grouped practice contact form with appropriate input types, instructions, help text, and browser validation.
- [ ] State clearly that the practice form does not send or store messages.
- [ ] Include the supplied silent video with native controls, timed visual descriptions, and a transcript, or equivalent permitted media with appropriate captions.
- [ ] Test keyboard navigation, links, media, and fictional valid/invalid form entries.

## Map the requirements to files

| File or area | What to build or review |
| --- | --- |
| index.html and about.html | Semantic regions, logical headings, working navigation, and skip links. |
| projects.html | Project articles and a media section with a visible transcript. |
| learning-log.html | A captioned table, a date, a quotation, and displayed HTML source. |
| contact.html | Labelled and grouped controls, help text, native validation, and a practice-only notice. |
| practice-result.html | A clear static destination that makes no message-delivery claim. |

Keep working from your own previous milestone. The complete download is a suggested solution, not a required starting template.

## Plan and build

1. Back up your previous milestone before editing.
2. Map each requirement to a page and identify the assets needed.
3. Implement one requirement at a time using the related lessons.
4. Test in a browser after each change.
5. Record evidence and revise unmet criteria.

Use the supplied practice pack for images and the silent video with its timed visual descriptions and transcript. You may substitute your own permitted media with equivalent alternatives. Image variants and their dimensions are supplied; no image editor is required.

<Accordion title="Hints">
Start with the existing folder structure. Check paths from each page, keep IDs unique, and choose elements by meaning. Test with fictional data. Revisit the relevant module checkpoint when you encounter a problem.
</Accordion>

## Acceptance checks

1. Open home and visit every page using your own navigation. Confirm that all destinations and local assets load.
2. Repeat a visitor journey without a mouse, including skip links and form controls.
3. Submit the practice form empty, then with an invalid email, then with complete fictional values. Record the expected and actual result for each case.
4. Play the supplied video over HTTP, enable its timed text, and compare the visible transcript. Record any browser limitation separately.
5. Review the page source, headings, labels, IDs, and file paths. Save changes and reload before retesting.

## Assessment rubric

| Area | Ready when | Needs revision when |
| --- | --- | --- |
| Content and structure | Required pages and features exist, with meaningful markup. | A feature is missing or its structure misrepresents the content. |
| Usability | Navigation, labels, native controls, and alternatives support the demonstrated journey. | A visitor cannot complete a required step or access equivalent information. |
| Reliability | Local assets and destinations resolve; invalid and valid form cases are recorded. | Paths fail or the form promises processing it does not provide. |
| Explanation | You can explain your choices and identify what CSS, JavaScript, or a backend would add. | The implementation is copied without understanding its behaviour. |
| Evidence | Checks, repairs, retests, and remaining limitations are documented. | Claims have no observations or unperformed checks are marked passed. |

Meet every required checklist item and every rubric row before moving on. Record **Needs revision** for a failed requirement and retest after repair. Record **Not tested** for checks you could not perform; discuss them with a reviewer before claiming completion. This rubric is not an automatic score or certification.

## Demonstrate and review

Keep the source files, local assets, a page map, and a short audit report. Demonstrate the required features and explain your decisions. For each checklist item record **Met**, **Needs revision**, or **Not yet attempted**, with evidence. A reviewer can add feedback separately; self-assessment is not automatic verification.





## What to hand over

- The complete portfolio folder, including local images and media.
- A README explaining how to open it and run the local server for media checks.
- An audit record with page, test, expected result, observation, repair, and retest.
- A short demonstration: what changed since the previous stage, one repaired defect, and the remaining limitations.

Keep these files for the final HTML challenge, then for CSS styling and JavaScript interactivity. Share them with the team's agreed reviewer when a review process is available; no external submission service is required for this course.

## Project materials

[Download the local practice assets](/assets/html/html-practice-assets.zip). Copy the images folder and, for later stages, the media folder into your project. Asset names and dimensions are listed in the pack README.

For the Intermediate and later milestones, use five main pages: index.html, about.html, projects.html, learning-log.html, and contact.html. A practice-result.html destination explains that no message is sent or stored. Optional supporting notes may have additional pages.
