## What you will learn

- Use native audio and video controls.
- Associate a WebVTT text track.
- Provide an equivalent transcript and test media paths.

## Media is content too

`audio` and `video` provide native players when you add `controls`. Nested `source` elements identify files and types. Add text and a download link as alternatives; a fallback inside video alone is not an adequate transcript.

Use `preload="metadata"` to suggest loading only basic information before playback. It is a browser hint, not a guarantee. Avoid forced autoplay. A video poster can provide a useful initial image.

## Captions and transcripts

`track` associates timed text such as captions with a video. WebVTT starts with WEBVTT, then uses cue timings and text. Captions normally include speech and relevant sounds; a transcript gives readable equivalent information outside the player. Visual information may need description as well.

Our supplied demonstration is a silent six-second animation showing three learning stages. Its text track describes the changing visual labels; it is a practice track, not an example of captioning speech. For spoken media, include accurate speech and meaningful sounds.

## Serve files locally

Browsers can restrict text tracks opened with file URLs. Extract the practice pack, then serve the folder over HTTP. If Python is installed, open a terminal in the folder and run `py -m http.server 8000` on Windows or `python3 -m http.server 8000` on macOS/Linux. Open `http://localhost:8000`. A code editor's local preview server is another option. Stop the server with Ctrl+C.

## Worked example

```html
<video controls preload="metadata" width="640" height="360"
       poster="images/study-wide.png">
  <source src="media/learning.webm" type="video/webm">
  <track src="media/learning-en.vtt" kind="captions"
         srclang="en" label="English descriptions" default>
  Your browser cannot play this video.
</video>
<p><a href="media/learning.webm">Download the silent practice video</a></p>
<h2>Transcript and visual description</h2>
<p>The animation displays Learn, then Practise, then Build.
There is no speech or other audio.</p>
```

[Download the practice pack](/assets/html/html-practice-assets.zip). Copy its images and media folders into your project. Enable the captions control during playback and compare it with the transcript. An audio-only example uses `<audio controls src="media/voice.wav">`, with your own permitted audio and a transcript; audio is optional for this exercise.

<Note>The practice pack is provided. You do not need to record yourself or find external media.</Note>

## Try it and observe

### Match a cue to the picture

Serve the practice files over HTTP. Turn on the English descriptions track and play the six-second clip. Check the three stages against the transcript and note their approximate timing. If timed text is missing, inspect the Network request for the VTT file and check its filename, WEBVTT header, and blank lines. Test the download link separately from playback.

## Practice challenge

Add the supplied video, timed text track, download link, and visible transcript to your projects page. Test over HTTP. Record whether playback and captions work in your browser.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

Check the Network panel if a track fails. Confirm the VTT file begins with WEBVTT and the path uses the same origin.

## Check your understanding

Is text inside the video element enough as the transcript? Would the supplied silent-video track be suitable for a spoken interview?

Write your answer before opening the explanation.

<Accordion title="Check your answer">

No. The fallback inside video may not be displayed when a browser supports the player. Keep a visible transcript outside it. An interview needs captions for the actual speech and meaningful sounds, plus any necessary descriptions of visual information.
