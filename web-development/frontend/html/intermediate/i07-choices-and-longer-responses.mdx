## What you will learn

- Create single-choice and multiple-choice controls.
- Supply explicit choice values.
- Collect longer text.

## Before you begin

Complete the Beginner stage project and earlier lessons in this module. Work in a copy of your growing portfolio.

<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## One choice or several?

Radio inputs sharing a name form a group in which only one can be selected. Give each option a label and explicit value. You can wrap the input in its label, as below, or connect a separate label using a unique id and matching for attribute. Related checkbox inputs allow independent selections; same-name checkbox values can repeat in submitted data.

`select` contains `option` elements for a choice list. A required select can start with an empty-value prompt. `textarea` is for longer responses; its initial text goes between its tags, not in a value attribute.

Unchecked checkboxes do not submit a value. Do not assume every displayed option will be present in a request. Keep labels visible.

## Worked example

```html
<label><input type="radio" name="session" value="morning"> Morning</label>
<label><input type="radio" name="session" value="afternoon"> Afternoon</label>
<label><input type="checkbox" name="interest" value="html"> HTML</label>
<label><input type="checkbox" name="interest" value="accessibility"> Accessibility</label>
<label for="level">Experience</label>
<select id="level" name="level" required>
  <option value="">Choose an option</option>
  <option value="new">New to coding</option>
  <option value="practising">Already practising</option>
</select>
<label for="message">What would help you learn?</label>
<textarea id="message" name="message" rows="4"></textarea>
```

Place these controls inside the practice form from the previous lesson. Click both radio options: selecting the second clears the first. Both checkboxes may remain selected.

<Note>Do not use placeholder text as the only explanation of a field.</Note>

## Try it and observe

### Observe which choices are submitted

Put the controls inside a form with a submit button and a local results page. Select one session and both interests; inspect the resulting query string. Then uncheck one interest and submit again. The unchecked checkbox should be absent. Giving the two radios different names would allow both to be selected, so keep their group name shared.

## Practice challenge

Add a session radio group, two optional interests, an experience select, and a learning-needs message to your practice form. Use explicit values and labels.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

<Accordion title="Need a hint?">
Radio buttons share a name to form a group. Their value attributes identify the individual choices.
</Accordion>

## Check your understanding

Why do radio options share a name but have different values? Where does a textarea’s initial text go?

Write your answer before opening the explanation.

<Accordion title="Check your answer">

The shared name identifies one selection group; each value identifies a different option. Initial textarea text goes between its opening and closing tags. It does not use an input-style value attribute.
