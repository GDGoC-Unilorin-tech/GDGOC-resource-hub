<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## A form collects values for a destination

`form` groups controls. `action` identifies the submission destination; `method` controls how the request carries data. GET puts form data in the URL query and suits retrieval such as a search. POST sends data in a request body, commonly for changes. Neither method implements processing by itself.

An input's `id` connects it to a label whose `for` matches. Its `name` is the key included during submission. An unnamed control can be visible but absent from submitted data.

## Safe local demonstration

The example navigates to a static results page. It demonstrates the query string but does not search or store anything. Run it through a local server to inspect normal HTTP behaviour; direct file navigation can vary between browsers.

## Worked example

```html
<p>Practice search: no real search is performed.</p>
<form action="results.html" method="get">
  <label for="query">Search term</label>
  <input id="query" name="q" type="search" required>
  <button type="submit">View practice destination</button>
</form>
```

Create results.html with a heading saying “Practice destination”. Submit a fictional term such as HTML. With HTTP serving, the destination URL includes ?q=HTML. The page cannot process that query without additional logic.

<Note>Use fictional data in practice URLs. Query strings can appear in browser history.</Note>

## Try it and observe

### Trace a submitted value

Serve the files locally, enter HTML in the search field, and submit. The destination should end in `results.html?topic=HTML` for the challenge. In a disposable copy, remove the input’s `name` and submit again. The control remains visible, but its value is missing from the query. Restore the name. Click the label to check the separate id/for relationship.

## Practice challenge

Build the search form and destination. Use the field name topic instead of q. Submit a fictional term and explain where its name and value appear.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

## Check your understanding

Will adding `action="results.html"` make that page perform a search? Is `id` a substitute for `name`?

Write your answer before opening the explanation.

<Accordion title="Check your answer">

No. A static destination can display a message but needs processing logic to search. The id identifies the control for its label and other references; name identifies its submitted value. Neither automatically creates a backend.

</Accordion>
