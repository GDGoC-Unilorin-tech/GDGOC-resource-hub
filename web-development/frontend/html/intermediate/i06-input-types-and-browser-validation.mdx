## What you will learn

## Types communicate expectations

`text` accepts general text, `email` supplies email syntax checking, `date` represents a calendar date, `number` suits numeric quantities, `password` obscures characters visually, and `file` lets a user choose a file. Native controls differ between browsers and devices.

Do not use number for telephone numbers or identifiers just because they contain digits. They may contain leading zeros or symbols and do not represent quantities.

## Constraints

`required` prevents an empty required field at submission. `min` and `max` constrain numbers or dates; `minlength` and `maxlength` apply to suitable text controls. A Boolean attribute such as required is enabled by its presence: writing required="false" still enables it.

Native validation helps users but can be bypassed. It does not confirm an email account exists, encrypt a password, or replace server-side checks.

## Worked example

```html
<form action="results.html" method="get">
  <label for="email">Practice email</label>
  <input id="email" name="email" type="email" required>
  <label for="sessions">Sessions per week</label>
  <input id="sessions" name="sessions" type="number" min="1" max="5" required>
  <label for="goal">Learning goal</label>
  <input id="goal" name="goal" type="text" minlength="10" maxlength="80" required>
  <button type="submit">Check sample entries</button>
</form>
```

Create results.html as in the previous lesson. Try empty fields, an invalid email, a quantity above five, and a short goal before valid fictional values.

<Note>If experimenting with password or file inputs, use dummy values and harmless files only; do not submit them through this GET example.</Note>
