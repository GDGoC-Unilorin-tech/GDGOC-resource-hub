## What you will learn

- Group related controls.
- Associate instructions with fields.
- Use autocomplete and explicit button types.

## Before you begin

Complete the Beginner stage project and earlier lessons in this module. Work in a copy of your growing portfolio.

<Tip>Examples labelled as body snippets go inside your existing document's body, not inside the MDX source of a live website. Complete HTML documents can be saved directly as .html files. Read the explanation for any head-only or intentionally broken examples.</Tip>

## Labels identify; instructions explain

Keep a visible label for each control. Placeholder text disappears during entry and does not replace a label. Put constraints into readable instructions rather than relying on an error after submission.

Use `fieldset` and `legend` to group related choices. `aria-describedby` associates extra help text with a control using the help element's ID. Use it for useful details, not to repeat every label.

Appropriate `autocomplete` tokens, such as name and email, help browsers assist entry. Use `type="submit"` for submission buttons and `type="button"` for buttons that should not submit. A button without an explicit type inside a form normally submits; reset buttons are usually unnecessary and can erase work.

## Worked example

```html
<form action="results.html" method="get">
  <p>Practice only. Use fictional details. No message is stored.</p>
  <label for="name">Name (required)</label>
  <input id="name" name="name" autocomplete="name" required>
  <fieldset>
    <legend>Preferred session (required)</legend>
    <label><input type="radio" name="session" value="morning" required> Morning</label>
    <label><input type="radio" name="session" value="afternoon"> Afternoon</label>
  </fieldset>
  <label for="message">Message (required)</label>
  <p id="message-help">Write 10 to 300 characters using fictional information.</p>
  <textarea id="message" name="message" minlength="10" maxlength="300"
            aria-describedby="message-help" required></textarea>
  <button type="submit">Check practice form</button>
</form>
```

Click a label to focus its field. Navigate through the form with the keyboard and try submitting without a session or with a short message.

<Note>The button label must not claim to send a real message when there is no backend.</Note>

## Try it and observe

### Test the label and the help separately

Click the message label and confirm that its textarea receives focus. Inspect that control in the Accessibility pane: its name should come from the label and its description from the help text referenced by `aria-describedby`. Compare those IDs in the source if help is missing. Use arrow keys to move within the radio group and Space to toggle a checkbox.

## Practice challenge

Improve your existing form with grouped session choices, visible required-field instructions, autocomplete for name/email, and associated message help. Test it without a mouse.

Attempt the task first. Save your source and inspect the result in your browser. Record what you expected and what you observed.

<Accordion title="Need a hint?">
Use one fieldset per related choice group, not one wrapper for every unrelated field.
</Accordion>

## Completion checklist

- [ ] Related choices have a meaningful legend.
- [ ] Labels remain visible and match controls.
- [ ] Help text IDs match aria-describedby.
- [ ] Keyboard and invalid-entry tests are recorded.

## Check your understanding

Can a placeholder replace the visible label? What happens if a button inside a form has no explicit type?

Write your answer before opening the explanation.
